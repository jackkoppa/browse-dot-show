# Scheduled ingestion on a Mac

How to set up a Mac so `bds ingest --all-sites` runs every night with nobody logged in, how to check on it, and what to do when something goes wrong.

The intended setup is a **dedicated Mac mini** (16 GB is enough) on AC power, with the local files on an external SSD that stays plugged in. A development Mac works too; differences are noted below.

## How it works

```
03:00  launchd (LaunchDaemon, runs as your user, no login needed)
         └─ node … bds schedule run                      (in the runner checkout)
              ├─ caffeinate (no sleep until the run ends); healthcheck /start ping
              ├─ checks: local files mounted + writable, free disk, power, network
              ├─ skip if another ingestion run holds the run lock
              ├─ update the runner checkout: fast-forward to origin/main;
              │  pnpm install + build if that changed anything
              ├─ bds ingest --all-sites                    (a child process: the updated code)
              └─ run record + log; Slack message; healthcheck success/fail ping
```

| Piece | Where |
| --- | --- |
| LaunchDaemon | `/Library/LaunchDaemons/com.browse-dot-show.ingest.plist` (generated by `bds schedule install`) |
| Wake schedule | `pmset repeat wakeorpoweron` 5 minutes before the run (`pmset -g sched` shows it) |
| Runner checkout | `browse-dot-show-runner` next to your main checkout: a git worktree, detached at `origin/main`, with the main checkout's gitignored config (`.env.*`, `.local-files-config.json`, …) symlinked in. Branch work in the main checkout never changes what runs at night |
| Settings | `~/Library/Application Support/browse-dot-show/schedule.json` |
| Logs | `~/Library/Logs/browse-dot-show/`: `scheduled/<run>.log` + `.json` (record) + `.summary.json` (pipeline), `transcription/` (worker logs), `ingestion-runs.md` (history of all runs), `launchd.log` (crashes before a run log opens). The newest 60 runs are kept |
| Run lock | `<localFilesPath>/locks/ingestion-run.lock`: a manual `bds ingest` and the scheduled run can't overlap |
| Notifications | `.env.automation`: `SLACK_WEBHOOK_URL`, `HEALTHCHECK_PING_URL` (both optional) |

Merges to `main` reach the runner at the next run. Terraform and client deploys never run here; they run in [GitHub Actions](github-actions-deploys.md).

## Set up a runner Mac

### 1. macOS settings (once, by hand)

On a **dedicated runner**:

- **Turn FileVault off** (System Settings → Privacy & Security → FileVault). With FileVault on, after any restart (a power cut, a macOS update) the Mac waits at a pre-boot unlock screen and nothing runs until someone types the password. The trade-off: a stolen Mac's internal disk is readable, which mostly means `.env.automation` (keys you can revoke). On a development Mac, leave it on and accept that a reboot pauses runs until you log in.
- **Never sleep, and restart after a power failure:**

  ```bash
  sudo pmset -c sleep 0
  sudo pmset autorestart 1
  ```

- **No automatic macOS installs:** System Settings → General → Software Update → ⓘ next to Automatic Updates: turn off "Install macOS updates" (downloads are fine). Install updates when you're around.
- **Optional, for running things remotely:** System Settings → General → Sharing → Remote Login (SSH).

A laptop works on a best-effort basis: lid open, on power. A closed laptop without an external display won't stay awake reliably.

### 2. Tools and the repo

Install [Homebrew](https://brew.sh) and the Xcode command line tools (`xcode-select --install`), then:

```bash
git clone https://github.com/jackkoppa/browse-dot-show ~/browse-dot-show
cd ~/browse-dot-show
./scripts/bootstrap.sh
```

`bootstrap.sh` installs the [`Brewfile`](../Brewfile) (`node@22`, ffmpeg, the AWS CLI, `whisper.cpp`), enables pnpm and builds. Scheduled runs use Homebrew's `node@22` by its absolute path, whatever node your shell uses.

> [!IMPORTANT]
> Don't clone into `~/Documents`, `~/Desktop` or `~/Downloads`: macOS blocks background jobs from reading those without extra permissions.

### 3. Local files, whisper, credentials

Plug in the SSD with the local files, copy `.env.automation` over from a Mac that has one (AirDrop, or `scp`; it holds the automation IAM user's keys), then:

```bash
pnpm bds setup machine \
  --local-files=/Volumes/<SSD>/browse-dot-show-local-files \
  --automation-env=~/Downloads/.env.automation
```

It's safe to re-run; it only changes what's missing:

- `.local-files-config.json` with `localFilesPath`
- `.env.local` from the `.env` template, with local whisper.cpp settings. For Homebrew's `whisper-cli`, `WHISPER_CPP_PATH` points to `~/Library/Application Support/browse-dot-show/whisper.cpp`, a folder laid out like a whisper.cpp checkout (`build/bin/whisper-cli` is a symlink to Homebrew's binary), so the transcription code doesn't change
- the whisper model (`large-v3-turbo`, about 1.6 GB, from Hugging Face)
- `.env.automation` copied in and `chmod 600`
- advice on FileVault, sleep, restart after power loss and Full Disk Access
- `bds doctor` (add `--aws` to check role assumption in every site account; read-only)

If you remove the copied file afterwards, delete it from `~/Downloads` too.

### 4. Notifications

Both are optional, but without the healthcheck nothing tells you when a run *didn't happen* (the Mac was off, or stuck at boot). Add them to `.env.automation`:

```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/…
HEALTHCHECK_PING_URL=https://hc-ping.com/<uuid>
```

- **Slack:** create an app at [api.slack.com/apps](https://api.slack.com/apps) → From scratch → Incoming Webhooks → on → Add New Webhook to Workspace → pick a channel → copy the URL. Every run posts: failures and skips, and successes too, as a daily heartbeat (change with `bds schedule install --notify-on-success=always|new-episodes|never`).
- **Healthcheck ([healthchecks.io](https://healthchecks.io), free):** add a check with Schedule **Cron** `0 3 * * *` (your run time), your time zone, and a **grace time of 8 hours** (a long run is fine; the run pings `/start` when it begins). Add Slack (or email) under Integrations. Copy the ping URL.

Check both:

```bash
pnpm bds schedule test-notifications          # a test success
pnpm bds schedule test-notifications --fail   # a test failure (the healthcheck goes red until the next success)
```

### 5. How many transcription workers

```bash
pnpm bds setup benchmark
```

Transcribes the same episodes with 1–4 parallel workers (each a `whisper-cli` process using about 2 GB with `large-v3-turbo`), recommends the fewest within 7% of the fastest, and offers to save it as `transcriptionWorkers` in `.local-files-config.json`. For reference, an M4 Pro with 64 GB did 24.7 / 35.2 / 47.6 / 50.7 audio minutes per minute with 1 / 2 / 3 / 4 workers.

### 6. Full Disk Access (if a run can't read the SSD)

A background job may need Full Disk Access to read an external volume. Try without it first (step 8); if a scheduled run is skipped with "can't read/write … Operation not permitted", grant it to the node binary that `bds setup machine` prints: System Settings → Privacy & Security → Full Disk Access → **+** → ⌘⇧G → paste the path.

That path is in Homebrew's Cellar and changes when `node@22` upgrades, which drops the permission. On the runner, pin it, and re-grant after you upgrade on purpose:

```bash
brew pin node@22
```

### 7. Install the schedule

```bash
pnpm bds schedule install --at=03:00
```

It shows what it will do, then:

1. creates the runner checkout (`browse-dot-show-runner` next to this checkout) and installs + builds it
2. writes `schedule.json`
3. with `sudo` (you're asked for your password): installs and loads the LaunchDaemon, and sets the daily wake for 02:55. A Mac has one repeating wake schedule; this replaces any existing one

`--print-only` prints the `sudo` commands for you to run instead. Re-run `install` to change any setting.

### 8. Check it works

```bash
pnpm bds schedule status                      # schedule, launchd state, wake, runner, recent runs, warnings
pnpm bds schedule run-now --dry-run           # the whole run in the runner checkout, ingest as a dry run (no AWS)
pnpm bds schedule run-now --via-launchd       # a real run, started by launchd (sudo launchctl kickstart)
```

Then the real test: set `--at` a few minutes ahead, **log out** (Apple menu → Log Out), wait, log back in and run `bds schedule status`. On a Mac that sleeps, also try it asleep rather than at the login window. Set the time back afterwards.

## Day to day

| | |
| --- | --- |
| Is it working? | `pnpm bds schedule status`, Slack, the healthcheck |
| Watch a run | `tail -f ~/Library/Logs/browse-dot-show/scheduled/<newest>.log` |
| Run it now | `pnpm bds schedule run-now` (in the terminal) or `--via-launchd` |
| Change the time | `pnpm bds schedule install --at=04:30` |
| Stop a running job | `sudo launchctl kill SIGTERM system/com.browse-dot-show.ingest` (the run stops whisper workers, releases locks and records `interrupted`) |
| Turn it off | `pnpm bds schedule uninstall` (`--remove-runner` also removes the runner checkout) |
| Manual ingestion | `pnpm bds ingest …` as usual. If it overlaps the schedule, whichever starts second exits (manual: code 75) or is skipped (scheduled) |

## Moving the SSD to another Mac

1. On the old Mac: `pnpm bds schedule uninstall` (or leave it; with the drive gone, its runs are skipped with "is the drive mounted?").
2. Set up the new Mac (above) with the same `--local-files` path. Locks left on the drive by the old Mac are ignored automatically (they name a different host).

## Testing changes to scheduling itself

The runner follows `origin/main`, so a change to `bds schedule` isn't used at night until it merges. To try a branch first, push it and point the runner at it:

```bash
pnpm bds schedule install --track=<your-branch>    # the runner follows origin/<your-branch>
pnpm bds schedule install --track=main             # afterwards
```

`bds schedule status` warns while the runner follows something other than `main`.

## Troubleshooting

| Symptom (`bds schedule status`, Slack) | Cause and fix |
| --- | --- |
| Skipped: `… doesn't exist (is /Volumes/… mounted?)` | The SSD isn't mounted. Plug it in; check it mounts without a login (Disk Utility: APFS, not encrypted) |
| Skipped: `can't read/write … Operation not permitted` | Full Disk Access (step 6) |
| Skipped: network unreachable | No network for 3 minutes after the wake. Check Wi-Fi/Ethernet; Ethernet is steadier |
| Failed: `Updating the runner checkout failed` | `pnpm install` or the build failed on the new `main` (the runner went back to the previous commit), or the runner checkout has local changes (`git -C <runner> status`). The next run retries |
| Failed: `bds ingest exited with code 1` | A pipeline error; the Slack message lists them, the run log has details |
| `crashed` | The run died without finishing: see its log and `~/Library/Logs/browse-dot-show/launchd.log` |
| No run at all, no Slack message, the healthcheck alerts | The Mac was off or asleep without a wake (`pmset -g sched`), stuck at the FileVault unlock screen after a restart, or the LaunchDaemon isn't loaded (`status` says so; re-run `install`) |
| `launchd.log` says `node: No such file or directory` | The node path in the LaunchDaemon is gone (a Homebrew or nvm change). Re-run `bds schedule install` (`--node=$(brew --prefix node@22)/bin/node`) |
